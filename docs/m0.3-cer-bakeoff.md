## Q-B1 recommendation

**Do not close Q-B1.** No measured engine is ≤ 10%. An unofficial Vision ruby-box variant (below) is also above 10% and is **not** the official CER.

**Working default (deferred, not wired to UI):** `manga_ocr` as a **sidecar** — still the lowest measured corpus CER on this GT (20.75% vs Cloud Vision 44.53%). Matches the PRD fallback of “Cloud/manga as default” on the manga side. Cloud Vision is scored and **worse** on glyph-as-drawn CER; do **not** switch the working default to Vision, and do **not** add Vision to the app UI. The box filter is not wired into the app either.

Do **not** add `google_mlkit_text_recognition` to `pubspec.yaml` yet (breaks `flutter run -d linux`). Flutter `OcrEngine` stubs stay unimplemented.

### Why Cloud Vision is 44.53% (not “no text”)

4/44 crops are **exact**, including `よぉ、相棒`, `誰か…`, `止めてくれ`, and `こんなひどいことされて、`. The other 40 all produced OCR; the engine is not failing closed.

Two buckets dominate the 236 edits:

1. **Furigana / ruby dumped into `fullTextAnnotation`.** Vision returns kana readings as extra lines next to the balloon kanji (`ひなこ` + `雛子`, `かあ` + `お母さん`, `うちゅうぐんだん` + `宇宙軍団`). After whitespace strip those readings are extra code points. 21/44 crops have the GT as a subsequence of the hypothesis (80 insertion-only edits). Dropping hiragana-only lines is **diagnostic only** → 165/530 = **31.13%** (still above 10%). That 31.13% is **not** the box-size filter in the next section. The official number does **not** drop ruby.
2. **Punctuation glyph mismatch.** `？` vs `?`, `！` vs `!`, `…` (U+2026) vs `...` or `･･･` (U+FF65 × 3), fullwidth `１００` vs ASCII `100`. Combining the unofficial hiragana-line drop with ASCII/fullwidth punct mapping → **25.28%**, still above 10%. The bake-off does **not** apply that mapping.

`page_0_b1` (cover overlay) is 31 edits for Vision vs 52 for manga-ocr. Vision is better on that one crop and still loses overall because of ruby + punct.

### Unofficial variant: box size + position (not a rescore)

Helm: furigana is the **small** text sitting with the kanji, so filter by **box size and position**, not by dropping hiragana-only lines (that is the 31.13% diagnostic above).

Live `DOCUMENT_TEXT_DETECTION` + `languageHints: ["ja"]` again on the same 44 PNGs (raw `fullTextAnnotation.text` still **44.53%**, 44/44, identical to the official dump). Word and paragraph boxes: [`tools/cer_bakeoff/results/cloud_vision_boxes.json`](../tools/cer_bakeoff/results/cloud_vision_boxes.json). Recompute: `python3 tools/cer_bakeoff/ruby_boxes.py --boxes tools/cer_bakeoff/results/cloud_vision_boxes.json --gt-dir <gt>`.

**What the boxes actually show.** These balloons are **vertical columns**. Ruby is **narrower** than the body column and sits to the **right** (larger x) with overlapping y. Image-y “above” is how vertical type stacks (a `、` sits above `て` in the same column) — using that as ruby would drop punctuation. Observed `W.w / B.w` for right-of, y-overlapping pairs: ruby cluster **0.24–0.44**, body cluster **≥ 0.51**.

**Rule (unofficial):** drop word W if some other word B in the crop has `W.w ≤ 0.5 × B.w`, `W.x ≥ B.x + 0.4 × B.w` (right, not same column), and y-overlap ≥ `0.3 × W.h`. Rejoin remaining words in Vision order. Same glyph-as-drawn CER (whitespace strip only).

### Why manga-ocr is 20.75% (not a total OCR failure)

25/44 crops are **exact**, including `よぉ、相棒`, `千鶴屋？`, and long balloons such as `こんな人にご飯なんて作らなくっていいよ`.

Two buckets dominate the 110 edits:

1. **`page_0_b1` (52 edits)** — red multi-column cover overlay on dark art, not a speech balloon. manga-ocr hallucinated a plausible sentence. Dropping this one crop would be 58/469 = **12.37%** (still above 10%). That is diagnostic only; the official number includes it.
2. **manga-ocr `post_process`** — the library maps `…` (U+2026) → `...` then `jaconv.h2z` → `．．．` (U+FF0E × 3). Under glyph-as-drawn CER that is a real error (`痛い…` vs `痛い．．．` is 3 edits on a 3-char GT). About **42** of 110 edits are this expansion. Collapsing those dots for diagnosis only → **12.83%**, still above 10%. The bake-off does **not** apply that collapse to the official score.

Remaining true substitutions are small (`お母ちんだ`, extra `しかし`, `ー` vs `――`, dropped `「」`, `いっへん`/`いっぺん`).

## Plan to close Q-B1

1. **Cloud Vision** on the **same** 44 PNGs: **done** (2026-10-03). Official corpus CER **44.53%** (236/530), 44/44 recognized. Does not clear 10%. An unofficial box-size/position ruby filter on the same dump is **21.32%** (113/530), 44/44 — still above 10%, still not the official number, and still not below manga-ocr. The 31.13% hiragana-line diagnostic is a different measurement.
2. **ML Kit JP** on a device/emulator: `TextRecognizer(script: TextRecognitionScript.japanese)` → JSON dump → `--predictions mlkit_ja=dump.json`. Still needed before choosing an on-device default. This Linux agent did not run ML Kit or an emulator.
3. Keep **manga-ocr sidecar** as working default until ML Kit is measured (or until a Vision post-process is specified as product OCR, re-scored, and actually beats 20.75%). Product OCR is balloon crops; cover overlays like `page_0_b1` may need a tighter crop, not a different engine.

Q-B1 closes when a measured corpus CER on this GT is ≤ 10%, or when Cloud + ML Kit are measured and we explicitly accept a working default above 10%. Cloud is now measured; ML Kit is not.
