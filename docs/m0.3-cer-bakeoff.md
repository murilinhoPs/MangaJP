# M0.3 — OCR CER bake-off (Q-B1)

PRD §18 M0 / §20.1: pick a default OCR engine if **any** measured corpus CER ≤ **10%** on the M0.2 kanji GT (44 balloon crops). Otherwise keep the best measured engine as a working default and list what is still needed to close Q-B1.

Harness: [`tools/cer_bakeoff/`](../tools/cer_bakeoff/README.md). Protocol: **glyph-as-drawn** (whitespace strip only — no NFKC, no kana fold, no `1`↔`１`).

## Engines

| Id | Engine | How to run |

| `mlkit_ja` | ML Kit JP text recognition | Android/iOS device; dump JSON into the harness |

Numbers in [`tools/cer_bakeoff/results/`](../tools/cer_bakeoff/results/) are filled by actually running engines. **No invented CER %.** A row that says `SKIPPED` means that engine did not run in that environment.

## Q-B1 recommendation

**Pending the live `manga_ocr` numbers in this PR.** Rule:

- If any **measured** corpus CER ≤ 10% → that engine is the Q-B1 default (tie-break: on-device ML Kit if it also clears 10%, else the lowest CER).
- If none ≤ 10% → keep the best measured engine as a **working** default (PRD: Cloud/manga) and still run the skipped engines before wiring the `/capture` overlay.

Production UI OCR is **not** wired in this milestone. Flutter `OcrEngine` stubs (`mlkit_ja`, `cloud_vision`, `manga_ocr`) stay unimplemented so Linux desktop and CI do not grow a mobile-only plugin.

## Closing the skipped engines

1. **Cloud Vision** — `CLOUD_VISION_API_KEY=… python3 tools/cer_bakeoff/bakeoff.py --gt-dir … --engines cloud_vision` then merge `results/`.
2. **ML Kit** — on a device, `TextRecognizer(script: TextRecognitionScript.japanese)` over the same 44 PNGs, write `predictions` JSON, `--predictions mlkit_ja=dump.json`. Do not add `google_mlkit_text_recognition` to `pubspec.yaml` until that bake-off (Linux plugin gap).
